02MetricPrecision · Recall trên tập cạnh
Precision = |E_gen ∩ E_gold| / |E_gen| Recall = |E_gen ∩ E_gold| / |E_gold| + thời gian (s), bộ nhớ (MB) trên macro

Trên micro, PyCG báo cáo nhị phân: complete = không có false positive, sound = không thiếu cạnh nào.

Báo P và R riêng biệt, không gộp F1. Hai trường phái đối lập: ARISE chỉ resolve trường hợp không mơ hồ, bỏ dynamic dispatch (cạnh giả khiến agent đi đường sai, tai hại hơn cạnh thiếu) → ưu tiên precision. CGM over-approximate: đưa tất cả override từ subclass vào, dùng Class Hierarchy Analysis → ưu tiên recall.

02MetricGold-Reachability@h · Coverage@budget · thời gian dựng
C = node trích từ issue description T = node từ gold patch δ = (1/|T|) · Σ min d(c, t) d = số hop Gold-Reachability@h = tỷ lệ instance có δ ≤ h

Áp vào ví dụ slide 02

C = { separability_matrix } T = { _cstack } δ = d(separability_matrix, _cstack) = 2 → instance này thuộc nhóm Hop 2

Node gold không tới được thì không agent nào tìm ra. Metric này chứng minh giá trị schema độc lập với chất lượng LLM — reviewer không thể phản biện "kết quả do model tốt".

Bảng cần báo cáo — phân bố theo hop

Schema Hop 0 Hop 1 Hop 2 3+ / ∞
File tree (không đồ thị) … … … …
+ CALLS … … … …
+ data-flow (ours) … … … ↓

Đưa 20% instance từ "3+ / ∞" xuống "Hop 1" là bằng chứng cấu trúc thuần tuý

Coverage@budget + IoU

Tỷ lệ dòng gold phủ được dưới budget 8.000 token — đo retrieval độc lập với reasoning của agent. Điều kiện không dùng bundling thì tính trên cửa sổ BM25 cùng kích thước token.

02MetricRecall@k · F1@k · IoU · Coverage@budget · Spearman ρ
Metric Định nghĩa
Recall@k Có ít nhất một vị trí gold trong top-k
F1@k Harmonic mean precision@k / recall@k — phạt over-prediction
IoU Intersection-over-union của tập dòng dự đoán và gold
ρ Spearman Tương quan giữa Function Recall@1 và Pass@1. Chỉ đo được nếu hai task chạy độc lập
